# 第一部分：一个宏观心智模型（最重要的一节）

如果这份文档你只读一节，读这节。

## Transformer 是什么：一条不断被修改的信息主干

**忘掉那张画满箭头的架构图。换一个视角：**

想象每个 token 都有一条从头贯穿到尾的**信息主干**（专业说法叫 residual stream，残差流）。这条主干的维度始终是 `d_model`，从输入到输出**从不改变**。

```
token 1 的主干:  ═══════════════════════════════════════>
token 2 的主干:  ═══════════════════════════════════════>
token 3 的主干:  ═══════════════════════════════════════>
                 ↑        ↑        ↑        ↑        ↑
                每一层都往主干上"加"一点东西, 从不推倒重来
```

**每一层做的事只有一件：读取主干上的当前内容，算出一个修正量，加回主干。**

这就是残差连接 `x = x + Sublayer(x)` 的真正含义——**不是"防止梯度消失的技巧"，而是整个架构的组织方式。**

## 两种"加东西"的方式，交替进行

| 子层 | 方向 | 干什么 | 一句话 |
|---|---|---|---|
| **Attention** | **横向** | 从**别的 token** 的主干上读信息，加到我的主干上 | 搬运 |
| **FFN** | **纵向** | 只看**我自己**主干上的内容，加工后加回去 | 提炼 |

```
       token1   token2   token3
         ║        ║        ║
    ┌────╫────────╫────────╫────┐
    │ Attention: 横向搬运         │   ← token 之间交流
    └────╫────────╫────────╫────┘
         ║        ║        ║
    ┌────╫───┐┌───╫───┐┌───╫───┐
    │  FFN   ││  FFN  ││  FFN  │   ← 各自独立加工, 互不通气
    └────╫───┘└───╫───┘└───╫───┘
         ║        ║        ║
        (重复 N 层)
```

**一横一纵，交替 N 次。这就是 Transformer 的全部。**

## 这个模型能解释掉的所有"为什么"

一旦建立了这个画面，前三天的很多细节就不需要单独记了，它们全都是这个画面的推论：

| 疑问 | 用主干模型直接解释 |
|---|---|
| 为什么输入输出形状必须一样？ | 主干宽度固定，才能一层层往上加 |
| 为什么要残差连接？ | 主干本身就是残差连接，不是附加技巧 |
| 为什么 LayerNorm 放在子层入口（Pre-LN）？ | 只清洗"读进来"的那一份，主干本身保持干净直通 |
| 为什么能堆到 96 层？ | 每层只做小修正，不推倒重来，所以叠加是安全的 |
| 为什么 attention 和 FFN 缺一不可？ | 只有横向 = 只搬不加工；只有纵向 = 各说各话 |
| 为什么需要位置编码？ | 横向搬运时不带位置信息，得在主干起点就注入 |

**如果你以后要向别人讲 Transformer，就讲这个模型，不要讲架构图。**

# 第二部分：必须内化的（只有 6 条）

这 6 条应该像"卷积是滑动窗口加权求和"一样，不假思索就能调用。

### 1. Attention 是一次可导的软检索

Q 拿着问题去和所有 K 比对，按相似度把所有 V 混合起来。

**"可导"是关键词**：硬检索（argmax）不可导，梯度传不过去，没法端到端训练。softmax 是为了可导才存在的。

### 2. Q、K、V 是三种角色，来源决定用途

| | 含义 |
|---|---|
| Q | 我要找什么 |
| K | 我是什么，供人搜索 |
| V | 我能提供什么内容 |

**K 和 V 必须同源**（一一配对：用 K 判断，取 V 的内容）。

**Q 的来源决定了 attention 的类型**——这是后面第四部分的关键。

### 3. 形状流：`(B, L, D)` 进，`(B, L, D)` 出，中间必有 `(L, L)`

```
(B, L, D) ──→ 中间产生 (B, h, L, L) ──→ (B, L, D)
                       ↑
              这个方阵是 O(n²) 开销的来源
```

**这条形状流是你以后 debug 的坐标系。** 任何时候模型报形状错误，你都应该能立刻定位是哪一环。

### 4. Attention 横向搬运，FFN 纵向提炼

见第一部分。**FFN 的参数量是 attention 的两倍**——Transformer 不只是 attention。

### 5. 三个"必须除以/必须屏蔽/必须注入"

| 操作 | 一句话理由 |
|---|---|
| `/√d_k` | 点积方差随维度增长 → softmax 饱和 → 梯度为 0 |
| `mask` 填 `-inf` | 屏蔽在 softmax **之前**，`exp(-inf)=0`；填 0 会变成 `exp(0)=1` |
| 位置编码 | attention 的三步计算都与顺序无关，必须外部注入 |

### 6. 复杂度 $O(n^2)$，这是所有长序列问题的根源

序列翻倍，显存变四倍。10 秒 30fps 视频 ≈ 58800 token，光注意力矩阵就 14GB。

**所以每篇处理长时序的论文都必须交代它怎么应对**（抽帧 / 压 token / 限窗口 / 稀疏注意力）。**这是你读 VLA 论文时的一个固定检查点。**

# 第三部分：要能讲清楚的（8 个问题）

这些不需要随时在线，但**组会被问到、面试被问到、写 related work 时要能展开**。理解了第一二部分，这 8 个应该都能现推。

1. Transformer 为什么取代了 RNN？（**并行**比效果更根本）
2. 为什么要多头？一组 QKV 只能表达一种关系，会被迫平均化。
3. 多头是不是 8 倍算力？**不是**，是把 512 维切成 8 份，总算力不变。
4. 多头为什么划算？瓶颈在"能有几个视角"，不在"每个视角多深"。
5. LayerNorm vs BatchNorm？单样本跨特征 vs 跨样本同通道；序列变长 + 推理 batch=1 决定了必须用前者。
6. 残差连接最重要的作用？让"原样传递"从难题变成送分题（学 $F(x)=0$ 很容易），梯度高速公路是第二位的。
7. 位置编码为什么用正弦而不是整数编号？有界、与序列长度无关、可外推。
8. self / cross / masked self 的区别？只差在 **Q 从哪来** 和 **mask 怎么设**。

# 第四部分：做研究时真正要动的三个地方

**这一节是这份文档里对你最有价值的部分。**

你以后做 VLA 研究，不会重写 Transformer——**你会拿现成的骨干，改三个地方**。几乎所有架构创新都发生在这三处：

## 接口一：Q、K、V 从哪来（决定信息怎么流动）

```python
mha(x, x, x)                    # self-attention: 序列内部交流
mha(lang, img, img)             # cross-attention: 语言查询图像 ← VLA 核心
mha(action_query, obs, obs)     # 可学习 query 查询观测 ← DETR/ACT 的做法
```

**第三种值得特别记**：ACT（你大二上要复现的两个之一）用的就是一组**可学习的 query 向量**去查询观测特征，一次性输出一整段动作序列。**它的创新点就在这个接口上。**

## 接口二：mask 怎么设（决定谁能看到谁）

| mask | 效果 | 用在哪 |
|---|---|---|
| 全 1 | 都能互相看 | 编码器、ViT |
| 下三角 | 只能看过去 | GPT、自回归生成 |
| 分块 | 模态内部随便看，模态之间受限 | 多模态模型 |
| padding | 屏蔽填充位 | 变长序列 |

**改 mask 是最便宜的架构改动**——不动任何参数，只改信息流动的规则。很多论文的贡献就是设计了一个新的 mask 模式。

## 接口三：输入怎么拼（决定模态怎么进来）

```python
# 最常见的做法: 各模态各自编码成 token, 拼成一个长序列
tokens = torch.cat([img_tokens, lang_tokens, state_tokens], dim=1)
```

**拼接顺序、每个模态占多少 token、要不要加模态标识 —— 这些都是设计空间。** OpenVLA、RT-2 的差别很大程度上就在这里。

> **记住这三个接口，比记住任何实现细节都有用。** 你读论文时可以直接问："它改的是 Q 的来源、mask、还是输入拼法？" 90% 的架构类工作都能被这三个问题定位。

# 第五部分：可以直接忘掉的

**明确列出来，就是让你不必再往脑子里放。**

| 内容 | 为什么可以忘 |
|---|---|
| 正弦编码的具体公式 | 用的时候复制，或者直接用 `nn.Embedding`（BERT/ViT 都这么干） |
| `exp(-log(10000)*2i/d)` 这个改写 | 数值稳定性技巧，知道"有这类考虑"就行 |
| $d_{ff} = 4 d_{model}$ | 经验值，没有理论必然性 |
| `contiguous()` 的内存原理 | **只记规则**：transpose 后接 view 就加它 |
| Pre-LN vs Post-LN 的历史 | 只记结论：现在都用 Pre-LN |
| `register_buffer` 的细节 | 只记规则：固定不变但要跟着 `.to(device)` 走的张量用它 |
| 参数量 1,050,624 这类具体数字 | 会算就行，不用记 |
| 8 个头分别学到了什么 | **本来就是编的**，实际训练出的头往往解释不了 |
| 原论文的 Encoder-Decoder 结构 | 现在主流是 Decoder-only，VLA 更是几乎不用完整 E-D |

# 第六部分：关于 A 档代码，我的修正

## 你说得对的部分

**"背下来"是错的说法**，我在文档里反复用"闭卷""凭记忆"，实际把你推向了背诵。这是我的表述问题。

**"可以交给 AI"也是对的**。真实工作里没人手写 attention——PyTorch 有 `F.scaled_dot_product_attention`，比手写的快（内部用了 FlashAttention），你复现 Diffusion Policy 时用的库里也全是现成实现。**如果目标是产出这段代码，练它就是浪费时间。**

## 但目标不是产出代码

**目标是：你脑子里要有那条形状流。**

举一个你半年后必然会遇到的具体场景：

> 你在复现 ACT，loss 降不下去。可能原因有二十个。你打印出中间张量，看到某处形状是 `(2, 5, 8, 64)`，而你预期是 `(2, 8, 5, 64)`。
>
> **如果形状流在你脑子里**：立刻知道是 `split_heads` 的 transpose 漏了，也立刻知道后果是"每个 token 在自己的 8 个头切片之间做注意力，token 之间毫无交流"。五分钟解决。
>
> **如果不在**：你只知道"形状不对"，然后开始改学习率、加正则、换优化器——这些都不会有用，因为问题不在那儿。

**AI 能替你写代码，但当你的模型跑出错误结果时，AI 不知道你的数据长什么样、不知道你改了什么。定位问题的人只能是你。**

## 所以标准修正为

**A 档的验收不是"默写出这段代码"，而是这三条：**

1. **能在脑中跑通形状流**——给定输入形状，说出每一步之后的形状
2. **能在空白文件里搭出结构**——查文档、抄参数顺序、复制签名都可以，但"下一步该干什么"要自己知道
3. **给一段陌生的 attention 实现，能十分钟内看懂它改了什么**

**"闭卷重写"只是一个 10 分钟的体温计，不是目标本身。** 如果你不做重写测试，但拿到一段魔改的 attention 代码能立刻说出它和标准版差在哪——**那你已经达标了，重写测试可以跳过。**

## 五段的取舍

老实说，五段里**真正必要的只有三段**：

| 段 | 判定 | 理由 |
|---|---|---|
| ① 训练循环五步 | **保留** | 每天都在用，且是所有 debug 的起点 |
| ② `nn.Module` 骨架 | **保留** | 你会自己写模块，这是必需的 |
| ③ `scaled_dot_product_attention` | **保留** | 形状流的载体，六行，成本极低 |
| ④ split/combine heads | **降到 B 档** | 只记住"heads 要挪到倒数第三维、transpose 后接 view 要 contiguous"这两条规则即可 |
| ⑤ Transformer Block | **降到 B 档** | 记住"两个子层，各是 `x + Sub(LN(x))`"这一句就够，代码可以查 |

**从五段减到三段。** 这是我基于你的质疑做的实际调整，不是敷衍。

# 附：如果要向别人讲 Transformer，讲这五句

1. **它是一条贯穿始终的信息主干，每层往上加东西，从不推倒重来。**
2. **加东西有两种方式：attention 横向从别的位置搬运，FFN 纵向自己提炼。**
3. **搬运的方式是可导的软检索——Q 问，K 答，V 给内容。**
4. **因为搬运不带位置信息，所以要在起点注入位置编码。**
5. **因为每个位置都要和所有位置比对，所以代价是 $O(n^2)$——这是所有长序列难题的根源。**

**五句话，覆盖了 Day 1~3 的全部核心。其余都是实现细节。**
