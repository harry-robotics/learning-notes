## 一、今天想通的一件事：Transformer 不是一张架构图，是一条主干

学到这里我才反应过来，之前一直在用错误的方式理解它——**把它当成一张画满箭头的流程图去背**，结果就是记不住、讲不出来。

换个视角就通了：

**每个 token 都有一条从头贯穿到尾的信息主干，维度始终是 `d_model`，从不改变。每一层做的事只有一件：读取主干上的内容，算出一个修正量，加回主干。**

```
token1 的主干: ══════════════════════════>
token2 的主干: ══════════════════════════>
                ↑      ↑      ↑
             每层往上加一点，从不推倒重来
```

加东西有两种方式，交替进行：

- **Attention = 横向**：从**别的 token** 的主干上读信息，加到我这里 → **搬运**
- **FFN = 纵向**：只看**我自己**主干上的内容，加工后加回去 → **提炼**

**一横一纵，重复 N 次。这就是 Transformer 的全部。**

这个画面能直接解释掉一堆之前死记的东西：形状为什么必须保持（主干宽度固定）、为什么要残差（主干本身就是残差，不是附加技巧）、为什么能堆 96 层（每层只做小修正）、为什么 attention 和 FFN 缺一不可（只搬不加工 / 只加工不交流）。

## 二、位置编码：解决 attention 的"色盲"

### 问题

Day 1 论证过：attention 的三步计算**没有一步用到位置**——算相似度只看两个向量的数值、softmax 求和与顺序无关、加权求和的加法更与顺序无关。

**所以「猫追狗」和「狗追猫」在它眼里是同一个输入。** 本质上 attention 把序列当成了**集合**。

对我的方向同样致命：「先抓取再抬起」和「先抬起再抓取」是两个不同策略；视频帧顺序丢了，就分不清杯子在被举起还是被放下。

### 三个方案是怎么死的

| 方案 | 死因 |
|---|---|
| 整数编号 0,1,2... | **数值无界**。序列长 500 时编码值是 500，而词向量在 ±3 范围，位置把语义淹没了 |
| 归一化到 [0,1] | **同一个数在不同长度里含义不同**。0.5 在长度 5 时是第 2 位，长度 500 时是第 249 位 |
| 可学习位置向量 | **无法外推**。训练时最长 512，遇到第 513 个位置就没有向量可用（但 BERT/ViT 确实在用它） |
| **正弦编码** | 三个问题全解决 |

### 直觉：像二进制计数器

看二进制每一位怎么变：最低位每加 1 就翻转（**最快**），最高位每 8 步才翻转（**最慢**）。**用几个不同变化速度的信号组合，就能唯一表示任意位置。**

正弦编码是同一个思路，把"翻转"换成"连续振荡"：

- **靠前的维度**：振荡快，像**秒针** → 区分相邻位置
- **靠后的维度**：变化慢，像**时针** → 区分远距离位置

512 维就是 256 组不同速度的指针，组合起来唯一确定一个位置。

**三个问题这样被解决**：sin/cos 永远在 [-1,1]（有界）；第 5 个位置的编码固定（与总长度无关）；是**公式不是查表**（任意位置都能算，可外推）。

### 为什么是"相加"不是"拼接"

**① 拼接会让维度翻倍**，后面每层参数量跟着涨（$W^Q$ 从 512² 变 1024²，参数量 ×4），代价太大。

**② 高维空间里相加不会真的搅混。** 512 维空间里随机取两个方向几乎必然接近正交，模型可以把语义放一组方向、位置放另一组近似正交的方向，**并存于同一个向量而互不干扰**。像收音机的不同频道共用同一段电磁波，靠频率区分。

## 三、FFN：Transformer 里被低估的一半

**先澄清一个我搞混过的问题：FFN 和 MLP 是同一个东西**，只是叫法不同（论文叫 FFN，3b1b 叫 MLP）。

但和 Phase 1 学的那个 MLP 有两点区别：

| | Phase 1 的 MLP | 这里的 FFN |
|---|---|---|
| 地位 | 就是**整个网络** | Block 里的**一个子层** |
| 形状 | 越来越窄 784→128→10 | **先胖后瘦** 512→2048→512 |

**为什么进出维度必须相同**：要做 `x = x + FFN(x)`，残差相加要求形状一致。这就是它不能一路变窄的原因。

**为什么中间要胖到 4 倍**：非线性变换需要空间。像**把一团纸展开、改、再折回去**，比不展开直接改灵活得多。2048 就是展开后的操作台。

### 最容易忽略的点：FFN 是逐位置独立的

**同一套权重，独立作用在每个位置上，位置之间在 FFN 里完全没有交流。**

代码上怎么实现的？**什么都没写**——`nn.Linear` 只作用在最后一维，前面的 `(batch, seq_len)` 自动当批次。和 attention 里用负索引是同一个道理。

**这正是它和 attention 的完美分工：一个横向，一个纵向。**

顺带记一个数：**FFN 的参数量是 attention 的两倍**（2×512×2048 vs 4×512×512）。所以"Transformer 就是 attention"这个说法是错的。

## 四、LayerNorm 放在哪，以及它和残差的关系

今天最容易混的一点，我卡了一会儿。

### LayerNorm 具体做了什么

对**一个 token 自己的 512 个数**做标准化：算这 512 个数的均值和标准差 → 减均值除标准差 → 乘可学习的 γ 加 β。

**只看这一个 token 自己**，和序列里其他 token 无关、和 batch 里其他样本无关。10 个 token 就独立做 10 次。

**为什么需要**：主干是累加的，几十层之后数值会越来越大，第 50 层面对的数可能比第 1 层大一个数量级。LayerNorm 保证**不管主干上的数长到多大，每个子层拿到的输入永远是标准尺寸**。

### "放在子层入口"的确切含义

```python
h = self.ln1(x)                    # ① 复制一份出来标准化
attn_out, _ = self.attn(h, h, h)   # ② 子层只看这份副本
x = x + attn_out                   # ③ 加回去的是【原来的 x】
```

**关键在第 ③ 行：`x` 是没被标准化过的原始值。**

```
     x（主干，从不被改写）
     │
     ├──────────────────┐  ← 旁路：原封不动
     ↓                  │
  LayerNorm             │  ← 只清洗"读进去"的那一支
     ↓                  │
  Attention             │
     ↓                  │
     └────→ + ←─────────┘
```

**所以：LayerNorm 只作用在读进子层的副本上，主干本身从头到尾没被归一化过。**

### 和残差的分工

- **残差连接** = 那条旁路本身，提供**从不被加工的直通主干**，梯度能无损传回第一层
- **LayerNorm** = 保证每个子层**读到的输入尺度稳定**

两者的配合方式就是 Pre-LN / Post-LN 的全部差别：

```python
x = x + Sublayer(LN(x))    # Pre-LN：旁路干净，梯度直通 ✓
x = LN(x + Sublayer(x))    # Post-LN：LN 挡在主干上，把高速公路截断了
```

**只需记结论：现在都用 Pre-LN。** 原论文是 Post-LN，训练深层模型不稳定，需要复杂的学习率预热。

## 五、完整流程

```
输入 → 变成 token 向量 → +位置编码（只加这一次）
                              ↓
    ╔═══ Transformer Block × N ═══════════════╗
    ║   x ──────────────┐                     ║
    ║   ↓               │ 旁路                ║
    ║  LN1              │                     ║
    ║   ↓               │                     ║
    ║  Multi-Head Attn  │  ← 横向搬运          ║
    ║   ↓               │                     ║
    ║   └───→ + ←───────┘                     ║
    ║         ↓                               ║
    ║   x ──────────────┐                     ║
    ║   ↓               │ 旁路                ║
    ║  LN2              │                     ║
    ║   ↓               │                     ║
    ║  FFN              │  ← 纵向提炼          ║
    ║   ↓               │                     ║
    ║   └───→ + ←───────┘                     ║
    ║   形状始终 (B, L, d_model)               ║
    ╚═════════════════════════════════════════╝
                              ↓
                     最终 LayerNorm → 任务头 → 输出
```

**三个要点**：位置编码只在最开始加一次（主干累加，起点注入会一直传下去）；中间形状从头到尾不变，所以能堆叠；**换任务只换最后的头**，骨干完全一样——ViT、GPT、OpenVLA 的主体是同一块东西。

## 六、代码骨架

```python
class TransformerBlock(nn.Module):
    def __init__(self, d_model, num_heads, d_ff):
        super().__init__()
        self.attn = MultiHeadAttention(d_model, num_heads)
        self.ff = FeedForward(d_model, d_ff)
        self.ln1 = nn.LayerNorm(d_model)     # 必须是两个独立的 LN
        self.ln2 = nn.LayerNorm(d_model)     # 各有自己的 γ、β

    def forward(self, x, mask=None):
        h = self.ln1(x)
        attn_out, attn_w = self.attn(h, h, h, mask)
        x = x + attn_out
        x = x + self.ff(self.ln2(x))
        return x, attn_w
```

**只需记一句话：两个子层，各是 `x + Sub(LN(x))`。** 其余查得到。

**两个 LN 不能复用一个**：LayerNorm 有可学习参数（γ、β 各 512 个），两个子层面对的数据分布不同，需要各自的参数。写成一个会强制共享，限制表达能力。这个错很容易犯，因为 LayerNorm 看起来"没有状态"。

## 七、今天最有说服力的实验

把 Day 1 那个抽象论证变成了两行能跑的代码：

```python
perm = torch.tensor([2, 0, 3, 1])          # 一个打乱顺序

# 不加位置编码
a, _ = block(x)
b, _ = block(x[:, perm, :])
torch.allclose(b, a[:, perm, :])           # → True

# 加位置编码
c, _ = block(pos_enc(x))
d, _ = block(pos_enc(x[:, perm, :]))
torch.allclose(d, c[:, perm, :])           # → False
```

- **True** = 置换等变：打乱输入，输出只是跟着打乱，**模型分不清顺序**
- **False** = 位置编码起作用了，打乱输入得到的是**真正不同的结果**

**这种"设计对照实验验证某个性质"的做法，比读十遍文字论证有用。** 以后遇到任何"某个性质是否成立"的疑问，都可以这样做。

## 八、易错点

> 真实卡住的地方，做完思考题后继续补充。

**1. 把 FFN 和 Phase 1 的 MLP 混为一谈。**
是同一类结构，但这里必须**先胖后瘦**且进出同维——因为要参与残差相加。Phase 1 的 MLP 是一路变窄的整个网络，这里只是一个子层。

**2. 没搞清 "LayerNorm 放在入口" 是什么意思。**
一开始以为是"先归一化 x，然后用归一化后的 x 继续往下走"。**错**——归一化的只是**读进子层的那份副本**，加回去的是**原始的 x**。主干从头到尾没被归一化过。

**3. 以为 Transformer 主要是 attention。**
FFN 的参数量是它的两倍。attention 只搬运不加工，**加工全靠 FFN**。
