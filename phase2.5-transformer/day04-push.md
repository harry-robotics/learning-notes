## 一、三种注意力其实是同一个东西

前三天只用过 self-attention。实际上常见的三种，**差别只有两处：Q 从哪来、mask 怎么设。**

| | Q 来自 | K、V 来自 | mask | 用在哪 |
|---|---|---|---|---|
| Self | 序列自己 | 序列自己 | 无 | BERT、ViT |
| Masked Self | 序列自己 | 序列自己 | 下三角 | GPT、自回归 |
| **Cross** | **序列 A** | **序列 B** | 通常无 | **VLA、多模态** |

计算过程完全相同，我写的 `scaled_dot_product_attention` 一个字都没改：

```python
mha(x, x, x)                 # self
mha(x, x, x, mask=causal)    # masked self
mha(lang, img, img)          # cross ← 只是 Q 换了来源
```

> **这个视角是读架构类论文最有用的工具**：看到任何新模型，先问"它改的是 Q 的来源还是 mask"。

**cross-attention 里 K 和 V 必须同源**，因为它们一一配对——先用 K 判断"这块是不是我要找的"，选中后取它的 V。分家了就是判断依据和取回内容对不上号。

**输出长度跟随 Q 不跟随 K**：5 个语言 token 进去，5 个向量出来，每个都拿到一份"与它最相关的图像内容的混合"。权重矩阵是 `5×196` 的长条，不是方阵。

**Encoder-Decoder 我跳过了**——原论文为机器翻译设计，现在主流是 Encoder-only（BERT/ViT）和 Decoder-only（GPT）。VLA 基本是 Decoder-only 主干 + cross-attention 接视觉。Decoder 里的 cross-attention 就是上面讲的那个，没有新东西。

## 二、终于让 loss 降下来了

### 为什么这步不能省

前三天做的全是"构造随机张量 → 检查形状 → 确认权重和为 1"。**这些验证的是代码没写错，不是模型能工作。** 唯一的证明是让 loss 真的降下来。

而且训练会逼我补上两个之前一直跳过的部件。

### 补上的两个部件

**Embedding：把离散符号变成向量。**

`nn.Embedding(vocab_size, d_model)` **本质是一张可学习的查找表**——给整数 `i`，返回第 `i` 行。

为什么不用 one-hot + 线性层？**数学上完全等价**（one-hot 乘矩阵就是取某一行），但要先构造一个巨大的稀疏矩阵再做乘法，纯属浪费。**Embedding 是同一个操作的高效实现，不是另一种方法。**

**输出头：把向量变回预测。** `nn.Linear(d_model, vocab_size)`，每个位置输出 V 个字符的分数。

### 数据怎么构造

**同一段文本，输入和目标错开一位：**

```
文本:  "hello world"
输入:  "hello worl"
目标:  "ello world"
```

位置 t 的输出预测位置 t+1 的字符。**一次前向同时训练了 64 个位置的预测任务**——这就是 Transformer 比 RNN 快的实际体现。

**而这正是 causal mask 必须存在的原因**：位置 t 若能看到 t+1，就直接看到答案了。

### 今天最值得带走的技巧：初始 loss 检查

**随机模型的交叉熵应约等于 $\ln(\text{vocab\_size})$。**

推导很简单：随机模型给每个字符相同概率 $1/V$，交叉熵 $= -\ln(1/V) = \ln V$。

| 实测 | 说明 |
|---|---|
| ≈ ln(V) | ✅ 正常 |
| 远高于 | 初始化或数据有问题 |
| **远低于** | ⚠️ **答案泄露，检查 causal mask** |

> **这个检查极其便宜——一次前向、一行代码，就能在训练三小时之前发现结构性错误。** 以后复现任何任务，第一件事都做它。

### 生成：一次一个字符

```python
logits = self(idx_cond)[:, -1, :]              # 只要最后一位的预测
probs = F.softmax(logits / temperature, dim=-1)
next_id = torch.multinomial(probs, 1)          # 按概率抽，不是取最大
idx = torch.cat([idx, next_id], dim=1)
```

**为什么不用 argmax**：每步都选最可能的会让生成陷入重复循环（"the the the..."）。采样才有多样性。

**temperature 就是 Day 1 学的 softmax 性质**：除以小于 1 的数 = 放大 logits 差距 = softmax 更接近 one-hot = 更保守。我当时做的 `a * 10` 实验，效果等同于 temperature = 0.1。

**`idx[:, -max_len:]` 截断的原因**：位置编码表只有 `max_len` 行，超了会索引越界。**这就是"上下文窗口"的由来**——GPT 说的 4k、128k 就是这个数。

## 三、ViT：图像怎么变成 token

### 唯一的问题

Transformer 吃一串向量，图像是三维张量，怎么转换？

**最朴素的想法（每个像素一个 token）直接爆炸**：224×224 = 50176 个 token，注意力矩阵 $50176^2 \approx 2.5\times10^9$。**这是 $O(n^2)$ 的又一次现身。**

**ViT 的解法：切成 16×16 的小块 → 196 个 patch。** 完全可以承受。

### 一行卷积搞定三步

理论上要：切块 → 拉平 → 线性变换。

```python
self.patch_embed = nn.Conv2d(3, d_model, kernel_size=16, stride=16)
```

**`stride` 等于 `kernel_size`，意味着核不重叠地扫过整图**，每次覆盖恰好一个 16×16 块，输出一个 `d_model` 维向量。**和三步做法数学等价，但只要一行。**

```
(B,3,224,224) → Conv2d → (B,768,14,14) → flatten(2) → (B,768,196) → transpose → (B,196,768)
```

> 又一个"论文写三步、代码写一步"的例子。**能认出它们是同一件事，这种识别能力比记住任何单个写法都有用。**

### CLS token

分类需要一个代表整张图的向量。ViT 的做法是**额外加一个可学习的 token 拼在最前面**，它不对应任何图像区域，**唯一作用是在 attention 中收集全图信息**。

和"对 196 个 patch 取平均"相比，**CLS 的权重是算出来的**——分类猫时可以集中看猫、忽略背景，而平均是一视同仁。但实际差距不大，很多工作直接用平均。

### 一个必须知道的代价

**CNN 自带局部性和平移不变性两个先验，等于免费送的知识。ViT 把它们全丢了**——任意两个 patch 都能交互，结构里没有任何空间假设。

**代价是：本来免费的知识现在必须从数据里学。** 所以 ViT 在小数据上明显不如 CNN，只有在 ImageNet-21k、JFT-300M 这种量级预训练后才反超。

> **通用规律：先验越少的模型上限越高，但需要的数据越多。**

**实践后果：没有人从零训练 ViT，全都用预训练权重。** 我以后做 VLA 也一样，视觉侧直接加载现成的。

## 四、这条线现在通了

```
图像 ──ViT patch embedding──→ 196 个图像 token ┐
                                                ├→ cat 成一个长序列 → Transformer → 动作头
指令 ──词嵌入────────────────→ N 个语言 token  ┘
```

**OpenVLA、RT-2 基本就是这个结构。** 回看提炼文档说的三个接口，现在每一个我都能看懂了：

| 接口 | 具体形态 |
|---|---|
| **Q/K/V 从哪来** | self / cross 的选择；ACT 用可学习 query 查询观测 |
| **mask 怎么设** | causal 不看未来；多模态里可设计模态间可见性 |
| **输入怎么拼** | 图像/语言 token 怎么拼、各占多少、顺序如何 |

## 五、代码里补上的几件事

**AdamW 取代 SGD。** Transformer 基本不用 SGD——不同层的梯度差好几个数量级，**一个统一学习率对某些层太大、对另一些太小**。Adam 给每个参数维护自己的学习率：梯度一直大的就把步长调小，反之调大。

**学习率 3e-4 是经验默认值**，注意比 SGD 的 0.01~0.1 小两个数量级，**换优化器不能沿用旧学习率**。

**`@torch.no_grad()` 和 `eval()` 是两件事，都要做。** 前者关掉梯度记录（省显存、更快），后者切换 Dropout 的行为（训练时丢、推理时不丢）。

**`view(-1, V)` 摊平算 loss**：`(32,64,V)` → `(2048,V)`。语义是"把 32 样本 × 64 位置看成 2048 个独立的分类任务"。**所有序列任务的 loss 都这么算。**

**`nn.Parameter` / `register_buffer` / 普通属性的三分：**

| | 会被训练 | `.to(device)` 跟着走 | 存进 checkpoint |
|---|---|---|---|
| `nn.Parameter` | ✅ | ✅ | ✅ |
| `register_buffer` | ❌ | ✅ | ✅ |
| 普通属性 | ❌ | ❌ | ❌ |

**CLS token 必须是 `Parameter`**——写成 buffer 它永远是全 0，整个机制作废，**而且不报错**。

## 六、易错点

> 做完思考题后继续补充。

**1. 两个"不报错但静默出错"的陷阱。**
- CLS token 写成 `register_buffer` → 永远全 0，分类效果差，查不出原因
- `generate()` 里忘了切回 `train()` → 后续训练全程 Dropout 关闭

这两个和 Day 2 的 `mask` 漏 `unsqueeze(1)` 是同一类问题：**形状合法、程序能跑、loss 正常，但结果是错的。**

**2. 换优化器忘了改学习率。**
SGD 的 0.01 拿到 AdamW 上会直接发散。两者差两个数量级。
